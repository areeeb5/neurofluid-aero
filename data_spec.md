# NeuroFluid-Aero — Data Spec

Shared contract for every stage of the data pipeline (CST airfoil geometry
-> XFOIL -> SU2 [optional] -> ANSYS -> 64x64 grid encoding). This is the
one place tensor shapes, file formats, and non-dimensionalization get
defined — update it here, not ad hoc in individual scripts, whenever a
stage's output format changes or a new stage is added.

## Conventions used everywhere
- Non-dimensional, chord-normalized coordinates: chord length `c = 1.0`,
  leading edge at `x = 0`, trailing edge at `x = 1`. All `(x, y)` are in
  units of chord fraction (dimensionless).
- Airfoil-fixed coordinate frame: `x` along the chord line, `y`
  perpendicular to it. Angle of attack is applied downstream (e.g. by
  XFOIL, or by rotating the grid), never baked into the stored geometry.
- Every data-generation script takes `--seed` and is fully reproducible.

## Phase 1, Step 1 — CST airfoil geometry
Generated by [`data_generation/cst_airfoil.py`](data_generation/cst_airfoil.py)
and [`data_generation/generate_airfoils.py`](data_generation/generate_airfoils.py).

### `data_generation/airfoils/<airfoil_id>.dat`
Selig-format coordinate file, plain text, one airfoil per file.
- Line 1: airfoil name/ID (e.g. `airfoil_0001`)
- Remaining lines: `x y`, whitespace-separated, 6 decimal places
- Point order: upper-surface trailing edge -> leading edge -> lower-surface
  trailing edge (the leading-edge point appears once, shared between the
  two surfaces). This is the format XFOIL expects via `LOAD <file>`
  (Step 4 of the pipeline).
- `x` in `[0, 1]`; `y` typically in `[-0.15, 0.15]` (chord fractions)

### `data_generation/airfoil_index.csv`
One row per airfoil, master index joining ID -> CST parameters -> derived
geometry stats.

| column | meaning |
|---|---|
| `airfoil_id` | unique ID, e.g. `airfoil_0001` |
| `filename` | corresponding `.dat` filename in `airfoils/` |
| `upper_0` … `upper_4` | 5 CST (Bernstein) coefficients, upper surface |
| `lower_0` … `lower_4` | 5 CST (Bernstein) coefficients, lower surface |
| `max_thickness` | `max(y_upper - y_lower)` over the chord, chord fraction |
| `max_camber` | signed camber-line value at the point of max `\|camber\|`, chord fraction (sign flips depending on whether the airfoil is cambered up or down there — this can make thickness/camber scatter plots look bimodal near camber=0, that's expected, not a bug) |

### CST parameterization
- Class function: `C(x) = x^0.5 * (1-x)^1` (standard round-nose/sharp-tail
  subsonic template)
- Shape function: Bernstein polynomial, 5 coefficients per surface,
  `S(x) = sum_{i=0}^{4} A_i * C(4,i) * x^i * (1-x)^(4-i)`
- Surface: `y(x) = C(x) * S(x) + x * te_half_thickness`
- x-distribution: cosine-spaced (bunched near LE/TE), 100 points per
  surface by default (`--n_points`)
- Trailing-edge thickness: small, configurable (`--te_thickness`,
  default `0.002` = 0.2% chord, split symmetrically ±half between upper
  and lower); `0` gives a sharp TE

### Validity filter (applied to every airfoil before it's accepted)
- Rejected if the upper surface is below the lower surface anywhere
  (self-intersecting)
- Rejected if max thickness < 2% chord or > 22% chord
- Filter is unit-tested (`generate_airfoils.py::run_validity_tests`)
  against a deliberately crossing case, a too-thin case, and a too-thick
  case (all must be rejected), plus one normal case (must be accepted),
  before any real data is generated.

### Sampling
- CST coefficients are drawn per airfoil from `Normal(mean, std)`, seeded
  by `--seed` (default 42) via `numpy.random.default_rng`, fully
  reproducible run-to-run.
- Upper-surface coefficients: `mean=0.15, std=0.18`, clipped to `>= 0`
  (biased positive).
- Lower-surface coefficients: `mean=-0.10, std=0.15`, clipped to `<= 0`
  (biased negative/small).
- This keeps most random draws near realistic airfoil shapes; the
  validity filter above catches the remainder.

## Phase 1, later steps (XFOIL, ANSYS, grid encoding)
Not yet defined — to be added here when those steps are implemented. Per
`CLAUDE.md`, all three data tiers (XFOIL / SU2 / ANSYS) must land on the
SAME 64x64 grid definition (SDF, inside/outside mask, x, y, angle of
attack, Reynolds number channels) and the same non-dimensionalization;
that grid spec belongs in this file once it exists, not redefined ad hoc
in any one script.
